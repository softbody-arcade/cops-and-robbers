# Lightning frequency implementation plan

Use the [frequency design](../specs/2026-11-18-lightning-frequency-design.md) with the project's subagent implementation and independent review workflow.

- [ ] **Host controls and sky contract.** Add `lightningMinSeconds` and `lightningMaxSeconds` to server config, the panel's paired-setting apply order and the Sky editor. Use the existing config validation/persistence paths. Test defaults, bounds, whole seconds, both directions of edits and paired updates. Snapshot the settings in `sky.pick` and include them in `sky.payload`, checking that later host edits leave the active sky and a late join in sync. Update the player and host references and exercise settings visibility.
- [ ] **Client schedule.** Replace the exponential interval in `strikes.lua` with a seeded uniform interval. Apply the sky's captured bounds at cursor creation or first use. Guard invalid/missing intervals, especially zero or nonfinite values, so the scheduling loop always advances. Preserve the seeded detail stream, single-delivery frame boundaries, transition weighting, rewind, and deterministic join behavior. Test fixed cadence starting at GO, variable bounds, malformed/old payloads, window boundaries and late joins against uninterrupted play.
- [ ] Review each task, fix and re-review findings, then independently review the complete branch. Run Lua, LuaJIT, Vue/HUD and package checks. Stage an archived reviewed revision on the local test server with its installed config preserved. Record the SHA and in-game steps.
