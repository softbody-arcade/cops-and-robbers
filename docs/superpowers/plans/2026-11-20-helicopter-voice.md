# Helicopter pursuit radio implementation plan

> **For agentic workers** · Use the repo’s subagent-driven-development skill for implementation and independent review. Track progress with the task checkboxes.

**Goal** — Give pursuing cops timely spoken reports of moves the helicopter sees, including a single natural sentence for two quick turns.

**Architecture** — The runner’s client, or the Practice host for an AI runner, observes the road and the aircraft’s sight together. The server validates each observation, picks a complete recording and schedules it once for the pursuit. Each eligible cop plays the packaged Ogg file locally.

**Tech stack** — BeamNG GE LuaJIT, BeamMP server Lua, Vue HUD, plain Lua fixtures, build-time speech synthesis and FFmpeg.

**Spec** — [Air One on the pursuit radio](../specs/2026-11-20-helicopter-voice-design.md)

## Global constraints

- Use `feat/heli-voice`. The coordinator maintains the ledger on main. Commit each tested task on the feature branch and have another agent review it. Run targeted Lua tests from the repository root with `lua tests/run.lua <test files>` and bytecode-check each changed game-side Lua file with `luajit -bl path/to/file.lua >/dev/null`.
- One-second turn-pair window, four-second continuation window, three-second deadline to start a maneuver line. Times use seconds. Keep at most one pending call and one playing transmission. Aim for roughly two seconds per recording where the line allows.
- Players will test provisional West Coast routes in the first build. Use the installed map and small original fixtures to pick candidates. A screenshot or player survey is optional. Keep enough evidence to distinguish a wrong local name from a wrong road match.
- Keep AI speech generation on the asset-authoring machine. Package complete English recordings, measured durations and a generic identity. Core gameplay works offline. Each player's radio switch controls playback independently of the rotor switch.

## Events shared between tasks

Task 5 owns the server-issued token and clock. For Task 3, inject a known token and clock offset in the client fixture. The wire payload for an observation is `{token, seq, at, clear, heading?, turn?, countedFromLeftSeq?, exit?, mouth?, place?}`. A break carries no route facts. On a car change or gap, reset history at both ends. The call payload is `{token, seq, id, seconds, start, expires}`, all times in server-clock seconds except `seconds`, which is the measured clip duration. The client keeps at most one waiting transmission.

## Review focus

| Input | Required result | Task |
| --- | --- | --- |
| An overpass crosses the tunnel mouth at another height | It cannot earn a tunnel call | 2 |
| A ground cop sees the runner during a brief break in the aircraft ray | The two visible turns cannot chain across it | 3–4 |
| A loss report is waiting when sight returns | Neither the obsolete loss nor a spurious reacquisition starts | 4 |
| A sound arrives late on a new flight, or while a player is switching roles | It cannot start or resume on the wrong client | 5–6 |
| An old preferences file, missing clip or unknown player name | Radio defaults on, missing files skip cleanly and an unfamiliar runner gets the generic line | 1, 6 |

### Task 2 · Recognize a maneuver and the two provisional West Coast routes

**Files** — Create `client/lua/ge/extensions/copsAndRobbers/radioRoad.lua`, `client/lua/ge/extensions/copsAndRobbers/radioPlaces.lua`, `tests/test_radio_road.lua` and `tests/fixtures/radio_west_coast.lua`. Reuse the graph shape in `roads.lua` and the nearest-road adapter in `copsAndRobbers.lua`.

- [ ] Define the pure interface `radioRoad.sample(state, sample, roads, places) -> facts`. A sample has monotonic time, position, vehicle forward vector, level and raw aircraft sight. Facts can contain a travel heading, turn, named exit or visible entry at a tunnel mouth. Test straight-to-left and straight-to-right across three-way junctions with two outgoing options. Drive the same bend on a two-link road, reverse through it, jitter between adjacent segments and jump between stacked roads. Expect no turn in those four cases. Run the new test and verify it fails before implementing the matcher.
- [ ] Use successive clear positions, connected drivable edges, vertical fit and forward travel to confirm the outgoing branch. Count alternatives after excluding the approach. Measure heading along the runner’s displacement using the game’s compass convention. Track one turn per committed junction. Reset the approach on obstruction, discontinuous movement or an ambiguous match. With no graph, clear movement can still establish a heading.
- [ ] Extend `radioRoad.sample` to return `countedFromLeftSeq=<sequence of the anchoring left>` only on the confirmed right after an observed left and two distinct legal right-hand junctions passed on the same road. Count each junction once across lanes and sampling ticks. A left-only junction and a grade-separated crossing add zero. Passing the third silently exhausts this count. Reset it on another committed turn, reversing course, ambiguity, missing samples or blocked sight. A new confirmed left starts a new count. Replay a left at 0 seconds, right-hand streets passed at 2 and 4 seconds, third right taken at 6 seconds, plus bypass, fourth-right and interrupted-sight traces. Assert the left sequence appears only on the qualifying right. Give the matcher the same observation sequence the reporter will send. Verify on an unnamed map as well.
- [ ] On the installed West Coast map inspect `city.sites.json` for `us_route_110_north`, `us_route_110_south` and `downtown_belasco`, plus tunnel volumes under `main/MissionGroup/tunnels/tunnel_zones/`. Use connected roads or a local engine trace to identify a city-bound ramp and a plausible downtown mouth. Record a small approach/exit gate for each, height limits, travel direction and a plain-language starting landmark in the fixture. Match the final visible approach through the mouth. A nearby area label alone cannot establish entry. Use the ordinal recording only if the approach’s exit order supports it. Expose map site identifiers for known recorded locations and map them to bounded voice labels. Unknown levels or unmapped names fall back to turn and heading calls.
- [ ] Replay the candidate ramp, its bypass, the road above it, the correct tunnel approach, its reverse and a parallel street with authored samples. Assert one named exit, one visible mouth and silence for false matches. Replay an unknown map and assert a generic turn. Run `lua tests/run.lua tests/test_radio_road.lua`, check bytecode and commit the matcher, mappings and fixtures.

### Task 4 · Schedule sentences on the server

**Files** — Create `server/CopsAndRobbers/cnr/radio.lua` and `tests/test_radio.lua`. Use the catalogue from Task 1. Keep scheduling free of network calls.

- [ ] Define `radio.observe(state, observation)` and `radio.tick(state, now, phase) -> call|nil`. A call contains clip ID, duration, increasing sequence, expiry and start time. A maneuver expires three seconds after its last turn or exit. Use the latest fresh clear sample for contact/reacquisition and the fresh blocked sample at transition into search for loss, each with a three-second start deadline. Write table-driven tests with a deterministic catalogue duration and clock. At 0 and 0.75 seconds expect one ordered pair. At 0 and 1.5 seconds, with the first already started, expect the appropriate continuation. At exactly 1 second a second turn already received before dispatch may pair. After four seconds start a new turn. Exercise all four pairs, three turns in succession, a dropped middle turn and a three-second-old pending call.
- [ ] Test priorities separately. A named ramp replaces an unsent turn. A confirmed third right after a left bypasses the ordinary pair hold and continuation window. It replaces any pending ordinary maneuver and is due within three seconds of the right, even if the left already aired. Use the named-exit line when the same right qualifies for both. Test the six-second trace through dispatch, including one call for the right and silence at both bypasses. One blocked sample discards unsent route calls. A loss requires prior visual contact and the aircraft entering search. Feed a confirmed mouth followed by blocked samples every 0.25 seconds through search at two seconds. Expect the named loss. In a second run insert a reporting gap and expect the mouth to be forgotten. A return before dispatch cancels pending loss. A return after dispatch earns one reacquisition. Start-of-flight contact uses the latest fresh clear sample after release. Refuel, grounded state and teardown clear the queue.
- [ ] Run the new suite red. Implement the scheduler using measured clip length for busy-until time. Select variants once at dispatch. Emit at most one call per tick, recheck deadlines after waiting to speak and use standalone wording when a previous maneuver was dropped. Run `lua tests/run.lua tests/test_radio.lua tests/test_radio_phrases.lua` and commit.
