# HUD App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Vue 3 UI app at bottom centre, placed automatically on join, with a status line and a smooth catch bar that replace the corresponding toasts.

**Architecture:** A pure Lua model (`copsAndRobbers/hud.lua`) turns client state into a display payload and extrapolates catch progress between server updates. It is unit-tested with stock Lua. The client extension pushes that payload to the UI via `guihooks.trigger("CnRHud", payload)` about 10 times a second. It also adds the app to the current layout with `ui_appLayouts` and removes it on leave. The Vue SFC only renders the payload.

**Tech Stack:** LuaJIT/Lua 5.1 subset (client), Lua 5.3 (server), Vue 3 SFC compiled by BeamNG 0.40's mod runtime (`@/services/events`), `make test`.

**Spec:** `docs/superpowers/specs/2026-11-15-hud-app-design.md`

## Global Constraints

- The app sits at bottom centre, about 520×90 px. Placement `{ bottom = "70px", left = "calc(50% - 260px)", width = "520px", height = "90px" }`.
- The app directive and app name are `copsAndRobbersHud`, and the folder is `client/ui/modules/apps/CopsAndRobbersHud/`.
- UI event name: `CnRHud`.
- Catch progress travels at 1% precision (server rounding 0.01). The display shows an integer percentage, floored.
- Runner: red, label `BEING CAUGHT`. Cop: blue, label `HOLDING RUNNER`.
- Status line format: `ROLE  m:ss | reset | info`. Reset is `Reset OK`, the server hint, or `Penalty`.
- Toasts for the status line and catch progress are suppressed only while the app is placed. Otherwise they stay as the fallback.
- Version becomes 1.3.0 (server `VERSION`, client `CLIENT_VERSION`, `mod_info` `version_string`).
- Client code must stay LuaJIT-compatible: no `//`, no `goto`, no integer division.

## Review Focus

1. Server updates stop mid-hold (lag): the bar must not run away. Extrapolation is capped at 0.3 s past the last sample (test in Task 2).
2. Progress 0.996: the display shows 99, not 100, until the server ends the round (test in Task 2).
3. Payload before the chase starts (prep, countdown, head start): the status line is hidden, but the app may show the catch bar never (test in Task 2).
4. The layout changes after join (BeamNG.Earth switches to its MP layout): the app must be added to the new current layout too (manual check in Task 4).
5. The app cannot be added (no current layout, or `addApp` returns false): the toasts must keep working (manual check in Task 4).

### Task 2: Pure HUD model

**Files:**
- Create: `client/lua/ge/extensions/copsAndRobbers/hud.lua`
- Modify: `tests/run.lua`: add `client/lua/ge/extensions/?.lua;` to `package.path`
- Test: `tests/test_hud.lua`

**Interfaces:**
- Produces (module `copsAndRobbers/hud`):
  - `hud.new() -> state`
  - `hud.catchSample(state, now: number, progress: number)`: records a server value (0..1)
  - `hud.catchAt(state, now: number) -> number`: extrapolates from the last two samples by their rate, for at most 0.3 s past the last sample, clamped to 0..1. It returns the last value when there is only one sample.
  - `hud.payload(state, now: number, info: table) -> table`, where `info = { active, role ("runner"|"cop"), chaseStart (clock or nil), resetAllowed, resetHint, penalty, infoText }`. It returns:
    - `visible`: equals `info.active`
    - `status`: `nil` unless `chaseStart`, otherwise `{ role = "RUNNER"|"COP", time = "m:ss", reset = string, info = string|nil }`
    - `catch`: `{ visible, percent = math.floor(p * 100), label, tone = "runner"|"cop" }`, with `visible = p > 0`
  - `hud.formatTime(seconds) -> "m:ss"`

- [ ] **Step 1: Write the failing tests** (`tests/test_hud.lua`)

```lua
local hud = require("copsAndRobbers/hud")

test("formatTime", function()
  assertEq(hud.formatTime(0), "0:00"); assertEq(hud.formatTime(192.7), "3:12")
end)

test("catchAt extrapolates between samples", function()
  local s = hud.new()
  hud.catchSample(s, 10.0, 0.10); hud.catchSample(s, 10.25, 0.14)
  assertNear(hud.catchAt(s, 10.35), 0.156, 1e-9)
end)

test("catchAt stops extrapolating 0.3 s after the last sample", function()
  local s = hud.new()
  hud.catchSample(s, 10.0, 0.10); hud.catchSample(s, 10.25, 0.14)
  assertNear(hud.catchAt(s, 12.0), 0.188, 1e-9)
end)

test("catchAt clamps to 0..1 and drains", function()
  local s = hud.new()
  hud.catchSample(s, 0, 0.98); hud.catchSample(s, 0.25, 0.99)
  assertEq(hud.catchAt(s, 0.5), 1)
  local d = hud.new()
  hud.catchSample(d, 0, 0.05); hud.catchSample(d, 0.25, 0.01)
  assertEq(hud.catchAt(d, 0.5), 0)
end)

test("single sample returns its value", function()
  local s = hud.new(); hud.catchSample(s, 3, 0.42)
  assertNear(hud.catchAt(s, 9), 0.42, 1e-9)
end)

test("payload hides status before the chase and shows catch per role", function()
  local s = hud.new(); hud.catchSample(s, 1, 0.996)
  local p = hud.payload(s, 1, { active = true, role = "runner", resetAllowed = false, resetHint = "Stop to reset" })
  assertEq(p.visible, true); assertEq(p.status, nil)
  assertEq(p.catch.visible, true); assertEq(p.catch.percent, 99)
  assertEq(p.catch.label, "BEING CAUGHT"); assertEq(p.catch.tone, "runner")
  local c = hud.payload(s, 1, { active = true, role = "cop", chaseStart = 0 })
  assertEq(c.catch.label, "HOLDING RUNNER"); assertEq(c.catch.tone, "cop")
end)

test("payload status line", function()
  local s = hud.new()
  local p = hud.payload(s, 200, { active = true, role = "cop", chaseStart = 7.3, resetAllowed = true, infoText = "Runner 640 m NE" })
  assertEq(p.status.role, "COP"); assertEq(p.status.time, "3:12")
  assertEq(p.status.reset, "Reset OK"); assertEq(p.status.info, "Runner 640 m NE")
  assertEq(p.catch.visible, false)
  local q = hud.payload(s, 200, { active = true, role = "runner", chaseStart = 0, penalty = true, resetHint = "x" })
  assertEq(q.status.reset, "Penalty")
  local h = hud.payload(s, 200, { active = true, role = "runner", chaseStart = 0, resetHint = "Stay still 4s to reset" })
  assertEq(h.status.reset, "Stay still 4s to reset")
  assertEq(hud.payload(s, 0, { active = false }).visible, false)
end)
```

- [ ] **Step 3:** Implement `client/lua/ge/extensions/copsAndRobbers/hud.lua` per the interface, using the Lua 5.1 subset. It must not reference engine globals.
- [ ] **Step 4:** `make test` → all pass.
- [ ] **Step 5:** Commit `feat: pure HUD model with catch extrapolation`.

### Task 4: Client integration, auto-placement, toasts, version, deploy

**Files:**
- Modify: `client/lua/ge/extensions/copsAndRobbers.lua`
- Modify: version strings (`server/CopsAndRobbers/main.lua`, client `CLIENT_VERSION`, `client/mod_info/CopsAndRobbers/info.json`, and the version tests in `tests/test_main.lua`)
- Modify: `README.md`, `docs/FEATURES.md` (a HUD section)

**Interfaces:**
- Consumes: `hud.new`, `hud.catchSample`, `hud.payload` (Task 2). The game provides `ui_appLayouts.getCurrentLayout()`, `.addApp(filename, appName, placement)`, `.removeApp(filename, zeroBasedIndex)`, `.setCurrentLayout(filename)` and `guihooks.trigger`.

- [ ] **Step 1: Push the payload.**
  - The extension does `local hud = require("copsAndRobbers/hud")` and keeps one `hudState`.
  - `onState` calls `hud.catchSample(hudState, clock, p)`.
  - `onUpdate` sends `guihooks.trigger("CnRHud", hud.payload(hudState, clock, info))` every 0.1 s while `active`. Once after `endRound` it sends `{ visible = false }`.
  - `info` comes from the existing locals: `active`, `role`, `chaseStart` (set by `startStatus`, cleared in `endRound`), `resetAllowed`, `lastHint`, `penaltyActive`, and `infoText` (refreshed by `gpsInfo()` when `gpsTarget`).
- [ ] **Step 2: Auto-placement.**
  - Every 2 s while connected (any time after `onExtensionLoaded`, not only in rounds), and only after the first 3 s following load:
    - `local layout = ui_appLayouts and ui_appLayouts.getCurrentLayout()`.
    - If `layout.filename` exists and none of `layout.apps` has `appName == "copsAndRobbersHud"`: call `addApp(layout.filename, "copsAndRobbersHud", PLACEMENT)`, then `setCurrentLayout(layout.filename)` so the UI refreshes, and remember the filename in `placedLayouts`.
  - `hudPlaced` is true when the current layout contains the app.
  - On `onClientEndMission` / `onExtensionUnloaded`: for each remembered filename, find the app's index in that layout (`getAvailableLayouts` or `getCurrentLayout`) and `removeApp(filename, index - 1)`, then `setCurrentLayout` on the current one.
  - Everything is wrapped in `pcall`, so a failing UI API never breaks the mod.
- [ ] **Step 3: Toasts.** The status-line toast in `onUpdate` and the catch toast in `onState` are skipped when `hudPlaced`.
- [ ] **Step 4:** `luajit -bl client/lua/ge/extensions/copsAndRobbers.lua` and `hud.lua` → no errors. Bump the version to 1.3.0 in all places, then `make test` → all pass.
- [ ] **Step 5:** Docs: `README.md` and `docs/FEATURES.md` get a "HUD" section (bottom centre, auto-placed and movable, status line, catch bar, toasts as fallback).
- [ ] **Step 6:** Commit `feat: 1.3.0 - HUD app with auto-placement`, then `make deploy` → the log shows `Cops and Robbers 1.3.0 loaded`.
- [ ] **Step 7: Manual check with the user, in game.**
  - The app appears at bottom centre after joining, including on BeamNG.Earth after its layout switch.
  - `/cnr test runner`: the status line appears at release, and the catch bar fills smoothly with the right colour and percentage.
  - The app is gone from the layout after leaving the server.
  - If the app does not appear, the toasts still show.
