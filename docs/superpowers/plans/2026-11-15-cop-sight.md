# Cop Line-of-Sight Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Cops' games detect sight of the runner. The server shares the runner's position live with all cops while he's in sight, and a close cop who can see him gets no route.

**Architecture:**
- The pure server module `cnr/sight.lua` owns the reports and the grace period.
- `round.lua` emits `live`, `spotted` and lost-sight `lastSeen` effects.
- `main.lua` wires up the `cnr_sight` event and the sends.
- The client module `copsAndRobbers/sight.lua` does the ray plan and the change/keep-alive logic, with an injected ray caster. The main client file runs it and shows the result.

**Tech Stack:** Lua 5.3 (server), LuaJIT (client), `make test`.

**Spec:** `docs/superpowers/specs/2026-11-15-cop-sight-design.md`

## Global Constraints
- **Config defaults:** `sightMaxMeters = 400` (0 = off), `sightGraceSeconds = 1.5`, `sightLiveIntervalSeconds = 1` (strictly positive), `sightNoRouteSeconds = 5`, `sightNoRouteMinMeters = 50`.
- **Interval and rules:** the BeamNG.Earth live interval is at least 3 s. The no-route distance is `max(sightNoRouteMinMeters, cop speed (m/s) × sightNoRouteSeconds)`.
- **Client checks:** 4×/s, only while the chase is running and you are a cop. Reports go out on change, plus a keep-alive every 5 s. Eye height is +1.2 m. Targets are the runner position +1 m up, ±2 m along his direction.
- **Text:** "IN SIGHT"; "Runner 640 m NE · live"; "SPOTTED · Nearest cop 1.2 km" and "HIDDEN · …".
- **Do not deploy:** the user says when the server is empty.
- **Version:** 1.7.0.

## Review Focus
1. **A cop disconnects while reporting sight:** his sight must stop counting. Tested in Task 2 via `playerLeft`.
2. **Sight reports from the runner, AI ids, spectators, or outside the running phase:** ignored. Tested in Task 2.
3. **The runner gets caught while in sight:** no live or lost-sight effects after the catch. Tested in Task 2.
4. **`sightMaxMeters = 0`:** no live effects, and the regular pings behave exactly as before. Tested in Task 2.
5. **A route cleared by "IN SIGHT"** comes back when the next live update says route=true. Tested in Task 4.

### Task 1: `cnr/sight.lua` and config
**Files:** create `server/CopsAndRobbers/cnr/sight.lua`; modify `cnr/config.lua` (DEFAULTS, plus `strictlyPositive.sightLiveIntervalSeconds`); create `tests/test_sight.lua`.

**Produces:**
- `sight.new() -> state`
- `sight.report(state, pid, seen, now)`
- `sight.forget(state, pid)`
- `sight.sees(state, pid, now, grace) -> bool`: seen, or lost less than `grace` ago.
- `sight.any(state, pids, now, grace) -> bool`
- `sight.noRouteDistance(speedMs, seconds, minMeters) -> number`

**Tests:**
- report true → sees.
- report false at t → still sees until t+grace, then not.
- forget → not.
- any over a list.
- noRouteDistance(27.8, 5, 50) ≈ 139; noRouteDistance(2, 5, 50) = 50.
- config.merge defaults include all five keys; `sightLiveIntervalSeconds = 0` is rejected.

### Task 2: round integration
**Files:** modify `cnr/round.lua` (state, `sightReport`, `tick`, `playerLeft`, `start`) and `tests/test_round.lua`.

**Produces:**
- `Round:sightReport(now, pid, seen)`: accepted only while `state == "running"`, for a player in the round, not the runner and not an AI.
- Effects:
  - `{kind="live", pos, noRoute={[pid]=true}, nearestCop}` every `sightLiveIntervalSeconds` while `sight.any` holds over the cops.
  - `{kind="spotted", spotted=true|false}` on transitions.
  - On a lost-sight transition: an immediate `{kind="lastSeen", pos, nearestCop}`, and `lastSeenAt = now`.
- While in sight, `lastSeenAt = now` (this suppresses the regular ping).
- All of it is skipped when `sightMaxMeters == 0`, when caught, or when there is no runner car.
- Add `sightReport` to the test-scoping wrapper list if it returns effects. It returns none.

**Tests** (`started()` releases at t=11; runner pid 1, cops 2 and 3):
- Live every 1 s, with no regular ping at 41.
- A close seeing cop (40 m) is in `noRoute`; a far one (300 m at 50 km/h) is not; a non-seeing cop is not.
- A lost report at 20 → still live at 21; at 21.6 a lastSeen plus spotted=false.
- spotted=true only once.
- Off at 0.
- Reports from the runner or during prep are ignored.
- After `playerLeft(2)` its sight no longer counts.
- No live after the catch.

### Task 3: server wiring
**Files:** modify `main.lua` (applyEffects `live`/`spotted`, `cnrOnSight` + RegisterEvent, setup payload `sightMaxMeters`, geo throttle) and `tests/test_main.lua`.

**Sends:**
- Each human cop gets `cnr_lastSeen {live=true, route=not noRoute[pid], pos|geo}`. In geo mode, live sends are skipped if the last one was less than 3 s ago.
- The human runner gets `cnr_nearestCop {dist}` on live, and `cnr_spotted {spotted}`.

**Tests:**
- `cnr_sight '{"seen":true}'` from pid 2 during the chase, then a tick: pid 2 receives `cnr_lastSeen` containing `"live":true`, and the runner receives `cnr_spotted`.
- From pid 1 (the runner): nothing.
- `cnr_roundSetup` data contains `sightMaxMeters`.

### Task 4: client
**Files:** create `client/lua/ge/extensions/copsAndRobbers/sight.lua`; modify `copsAndRobbers.lua`, `ai.lua` (`M.runnerObject()`), `tests/client_stubs.lua` (`castRayStatic`, `MPVehicleGE.getVehicles`, `log`) and `tests/test_client.lua`.

**`copsAndRobbers/sight.lua`:**
- `sight.visible(eyePos, runnerPos, runnerDir, maxMeters, cast) -> seen, dist`. `cast(origin, dirNormalized, len)` returns the hit distance; a target is clear when the hit distance ≥ len − 0.5.
- `sight.new()`
- `sight.step(state, clock, seen) -> shouldSend`: on change, or 5 s since the last send.

**Main file:**
- Restore `runnerId` from setup. Keep `sightMax` from setup.
- `updateSight()` in `onUpdate`, at 0.25 s:
  - The runner object is the AI runner, or the MP vehicle whose key starts with `runnerId .. "-"` and that is spawned and not deleted.
  - Send `cnr_sight {seen}`, and log the change with its distance.
- `onLastSeen`:
  - `live` with `route == false` → clear the route and show "IN SIGHT".
  - `live` with a route → the route plus " · live".
  - A regular ping → as today, without the suffix.
- The GPS refresh keeps the suffix.
- `cnr_spotted` and nearest-cop are combined for the runner.
- `endRound` resets the sight state.

**Tests:**
- A cop with a clear ray reports seen=true once, then a keep-alive after 5 s.
- A blocked ray gives seen=false.
- A live route=false update gives status info "IN SIGHT"; then a live route=true update gives "· live" with a route set.
- A runner who gets spotted=true and nearestCop shows "SPOTTED · Nearest cop".
